# Our Services: same Public Services UI, PetCare-only data

The route /nearby/our/:kind now mounts the **existing** NearbyPlaces component in mode=our, keeping its original breadcrumb, mode switcher, category strip, city selector and free-form city search, GPS control, radius and hours filters, 2GIS MapGL map and sidebar result cards. Public Services mode=public still calls the existing 2GIS public Places API and its original details modal.

The Our mode's only differences are that the search action asks the existing public approved-clinic API (never the 2GIS business listings) for PetCare branches, resolves map points using /api/clinic-location?clinicId, filters by category / radius / published working hours, and opens a PetCare booking modal instead of the public-contacts modal. Clinics with an unresolved map link but a matching city may still appear as result cards; only exact coordinates make pins. Bookings still use the authenticated owner pet-sync and requests API.

When a user clicks a map marker or result, a matching modal opens in place over the same map. The modal shows verified clinic data, published services and prices, signed-in owner pets, optional veterinarian choice, preferred date and time in the clinic's local time zone, optional contact phone and notes. It shows only doctors returned by GET /api/clinics/:id/doctors, which requires a clinic to be approved and exposes only active vets' names, IDs and specialties, not emails or staff permissions. Booking POST verifies doctorId belongs to the approved branch and is active, then stores doctorId, doctorName and optional contactPhone in the appointment. If no published services exist, the request button is disabled and the UI explains why. If there are no doctor profiles, the clinic can assign any available vet; no fake names are inserted.

Test both modes side by side before promotion. A pending or rejected clinic must never show in Our Services. Existing ImageKit, Supabase, Firebase Auth and original public map code remain intact.
